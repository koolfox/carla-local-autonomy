# تست Voxel کنار Traffic Manager

این تحویل یک **نمای هندسی تخمینی از همان RGB رانندگی** است. مدل آمادهٔ
[Depth Anything V2 Metric Outdoor Small](https://huggingface.co/depth-anything/Depth-Anything-V2-Metric-Outdoor-Small-hf)
عمق را از تصویر پیش‌بینی می‌کند و هندسهٔ موجود پروژه، سطح‌ها را به Voxel تبدیل
می‌کند. این مدل، TemporalVoxelNet آموزش‌دیدهٔ خودمان یا کنترل‌کنندهٔ خودرو نیست.

## اجرای سریع

روی کامپیوتر Operator، در ریشهٔ پروژه:

```bash
uv sync --extra vision --extra voxel --group dev
```

Operator را با فرمان قبلی دوباره اجرا کنید. این تغییر به آپدیت Worker ویندوز
یا نصب PyTorch روی آن نیاز ندارد.

1. در **Vision** گزینهٔ **Voxel (RGB depth)** را روشن کنید؛ برای مک Apple Silicon
   دستگاه **MPS** را انتخاب کنید. Detection مستقل است و می‌تواند خاموش بماند.
2. کنترل خودرو را **Traffic Manager** انتخاب کنید و Session را شروع کنید.
3. تصویر خام همچنان پیش‌فرض است. برای بررسی مدل، **Voxel** را بالای تصویر بزنید.
4. دانلود حدود ۱۰۰ مگابایتی مدل فقط در اولین استفاده انجام می‌شود؛ loading و خطا
   جداگانه نمایش داده می‌شوند. دانلود/استنتاج در مسیر کنترل یا Worker اجرا نمی‌شوند.
5. با **Stop & Save** خروجی‌ها زیر پوشهٔ همان run ثبت می‌شوند.

## خروجی و مرز ادعا

- تصویر منبع و Voxel مربوط به **یک فریم** هستند؛ شناسهٔ فریم ثبت می‌شود.
- مبدأ، دوربین جلویی است؛ X جلو، Y راست و Z بالا. این نما از pose/actor/waypoint
  کارلا استفاده نمی‌کند و نباید مبدأ دوربین را با مرکز خودرو اشتباه گرفت.
- فاصلهٔ متری، تخمین monocular است؛ کالیبراسیون دقت روی CARLA انجام نشده است.
- فضای دیده‌نشده، پشت مانع و خارج دید unknown باقی می‌ماند؛ free به معنی مسیر امن نیست.
- رنگ سطح بیانگر ارتفاع است، نه کلاس جاده، جدول یا خط. semantic segmentation و
  lane detection در این تحویل وجود ندارند.
- پردازش جدید حداکثر دو بار در ثانیه و newest-only است. مصرف GPU ممکن است بر
  کارهای ML هم‌زمان اثر بگذارد؛ هیچ ادعای ۶۰ FPS برای Voxel نداریم.
- فرمان Traffic Manager تغییر نمی‌کند. این نما هیچ ترمز، steering یا مسیر پیشنهادی ندارد.

فایل‌ها: `voxel-view.json` هویت مدل/نسخه/هش و محدودیت‌ها؛ `voxel-view.jsonl`
شناسهٔ فریم و زمان پردازش؛ `latest-voxel.npz` آخرین occupancy با ترتیب ZYX؛
`latest-voxel.jpg` نمای آخر؛ و در صورت فعال بودن ضبط، `voxel-view.mp4` با ۲ FPS.
ویدیو آخرین نتیجهٔ کامل را تکرار می‌کند؛ نگاشت فریم‌های ویدیو به منبع در JSONL است.
برای آموزش، MP4 نمای Voxel جایگزین RGB و برچسب‌های هم‌فریم نیست.

## ادامهٔ مورد توافق

اولویت بعدی، **پایداری Apply گاراژ با اندازه‌گیری زنده** است؛ این PR مدعی رفع آن نیست.
بعد ورود checkpoint آموزش‌دیدهٔ RT-DETR و ارزیابی detection مقابل برچسب‌های CARLA.
Traffic Manager، teacher حرکت است؛ ground truth تشخیص باید با visibility و فریم RGB
هماهنگ باشد، نه صرفاً فهرست تمام actorهای دنیا.

Waypoint می‌تواند به تصویر **همان فریم** project شود و به‌عنوان target مسیر/نقاط
یا ماسک آموزشی ذخیره شود. این خواسته در مسیر #69/#70/#62 باقی می‌ماند: خروجی
privileged teacher مجاز و مشخص؛ ورودی مدل deployable همچنان RGB. خط waypoint
را نباید تمام سطح جاده یا تمام فضای قابل رانندگی فرض کرد. آموزش مدل هندسی/Temporal
Voxel و کنترل با supervisor همچنان کار جداگانهٔ #31/#32/#63 است.

## ورود مدل دیگر

برای checkpoint سازگار با **Ultralytics RT-DETR**، فایل `.pt` را داخل `models/`
پروژه قرار دهید، فهرست مدل‌های workspace را تازه کنید و در Vision همان فایل را
با backend RT-DETR انتخاب کنید. تطابق label/classهای checkpoint با taxonomy ارزیابی
باید جداگانه بررسی شود. صرف پسوند `.pt` به معنی سازگاری هر مدل PyTorch نیست؛ معماری،
preprocess و output contract نیز باید مشخص باشند. مدل ناشناس را trusted فرض نکنید.

Adapter این نمونه در `carla_vision/voxel/rgb_depth.py` است؛ قرارداد مدل Temporal
Voxel در `carla_vision/voxel/contracts.py` قرار دارد. مسیر generic ONNX/perception
چندوظیفه‌ای را به‌اشتباه موجود یا تکمیل‌شده معرفی نمی‌کنیم.
